## Summary

Scope, architecture and the plan are documented, with concrete defaults for building the MVP. The planned app has two outputs: ranked, captioned 9:16 clips and a 16:9 highlights video. The initial setup targets a laptop; collection/storage can be shared and hosted deployment remains an option. The Python package has a `synth` command for deterministic fake VOD datasets, configuration, logging, a shared FFmpeg runner, a Helix metadata client, viewer-clip fetching, a pseudonymizing chat replay parser, the `ingest` command for one VOD, VOD audio download with 16 kHz mono normalization, vertical-MP4 export (cut, reframe, burned-in captions, encode; `autoclipper export` and the API's export endpoints), VOD time windows and viewer-clip moments, chat and audio features per window, the step-1 evaluation, candidate generation in the `AnalysisResult` format, the four baselines, the `train` command for logistic regression and LightGBM, the `analyze` command (one VOD in, ranked moments out: ingest → features → scoring → candidates, with the contract's warnings and failure codes), and the backend API (`autoclipper serve`), whose jobs run the real analysis pipeline by default. Python and frontend tooling run in CI. The Next.js frontend has the start, channels, library, progress, results (cards + whole-stream timeline view), highlights dialog, and clip editor screens (#29, #30, #31, #67, #72, #164), connected to the FastAPI backend via `NEXT_PUBLIC_API_ORIGIN` (#33) with in-browser mock mode still available. **There is no real dataset or model trained on real data yet, and the pipeline has not been run against real Twitch VODs.** No results exist.

## Known issues / caveats

- The Python setup was tested locally on Windows only; Linux runs in CI (Ubuntu). Nobody has tried macOS yet.
- Chat replay and VOD download rely on unofficial tools ([data sources](../data/data-sources.md)).
- **Viewer-clip positions are clip ends.** Helix `vod_offset` marks where a clip ends (+0.7 s), not where it starts ([exp-002](../../experiments/exp-002-clip-offset-check/README.md), confirmed in [exp-003](../../experiments/exp-003-clip-end-confirmation/README.md)). Since #126 moments, labels (rules `v1`), candidates, the ±15 s evaluation match and viewer-clip exports read a clip as `[vod_offset_s − duration_s, vod_offset_s)`; ingest still stores Helix's value unchanged. Analyses saved before #126 keep their old, one-clip-length-late viewer-clip spans until the VOD is analyzed again. About one clip in five is still more than 2 s off (outliers up to 34 s); no per-clip correction is made. Clip coverage was measured in the pilot: no clip without a VOD offset and no clip-search range at the limit ([pilot report § 3](../data/pilot-report.md#3-issue-35-metrics)).
