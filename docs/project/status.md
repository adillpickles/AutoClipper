## Summary

Scope, architecture and the plan are documented, with concrete defaults for building the MVP. The planned app has two outputs: ranked, captioned 9:16 clips and a 16:9 highlights video. The initial setup targets a laptop; collection/storage can be shared and hosted deployment remains an option. The Python package has a `synth` command for deterministic fake VOD datasets, configuration, logging, a shared FFmpeg runner, a Helix metadata client, viewer-clip fetching, a pseudonymizing chat replay parser, the `ingest` command for one VOD, VOD audio download with 16 kHz mono normalization, vertical-MP4 export (cut, reframe, burned-in captions, encode; `autoclipper export` and the API's export endpoints), VOD time windows and viewer-clip moments, chat and audio features per window, the step-1 evaluation, candidate generation in the `AnalysisResult` format, the four baselines, the `train` command for logistic regression and LightGBM, the `analyze` command (one VOD in, ranked moments out: ingest → features → scoring → candidates, with the contract's warnings and failure codes), and the backend API (`autoclipper serve`), whose jobs run the real analysis pipeline by default. Python and frontend tooling run in CI. The Next.js frontend has the start, progress, results (cards + whole-stream timeline view), highlights dialog, and clip editor screens (#29, #30, #31, #67, #72), connected to the FastAPI backend via `NEXT_PUBLIC_API_ORIGIN` (#33) with in-browser mock mode still available. **There is no real dataset or model trained on real data yet, and the pipeline has not been run against real Twitch VODs.** No results exist.
